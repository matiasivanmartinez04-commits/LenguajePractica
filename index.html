1. ¿Qué es un Sistema Embebido?

Computación general vs. computación física

Las computadoras estándar (PCs, notebooks, servidores en la nube) son de propósito general: ejecutan múltiples tareas en paralelo, interactúan fuertemente con el humano (teclado, mouse, monitor) y su software cambia constantemente según la necesidad operativa diaria.

Un Sistema Embebido (o empotrado/integrado) es, en cambio, una infraestructura informática optimizada para cumplir una sola función específica. Definición operativa de la cátedra:

«Es un sistema de computación diseñado para controlar, monitorear o recibir datos de una infraestructura física o proceso específico, integrado habitualmente dentro del propio dispositivo que gestiona.»

Cuadro comparativo para la gestión

Computación TradicionalSistemas Embebidos
Propósito general y multitareaFunción única y dedicada
Interacción directa con humanosInteracción con variables del entorno
Memoria y procesamiento masivosRecursos estrictamente limitados
Software modular e intercambiableFirmware estático y repetitivo

La analogía del rol laboral

Para entender la asignación de recursos en una pyme: una PC es como un asistente administrativo (el generalista: liquida sueldos, envía correos, edita videos). Un sistema embebido es como un operario técnico (el especialista): está programado para abrir exactamente una válvula cuando la presión pasa de cierto límite, de manera perfecta.

Casos reales en gestión

  • Controladores de acceso (SUBE / tarjetas): leen el chip, verifican permisos en las bases de datos y activan molinetes.
  • Climatización inteligente (HVAC): sensores miden temperatura y regulan compresores para optimizar el gasto de energía.
  • Logística y frenos ABS: monitorean la rotación de ruedas en camiones de flota para prevenir accidentes.

Arquitectura de todo sistema embebido

ENTRADAS → PROCESAMIENTO → SALIDAS
  • Entradas (Sensores): capturan la realidad (luz, calor, botones).
  • Procesamiento (Microcontrolador): aplica la regla lógica del negocio.
  • Salidas (Actuadores): modifican la realidad física (motores, luces, alarmas).

¿Qué es Arduino?

Es una plataforma de código abierto basada en hardware y software flexibles: el hardware (placa con microcontrolador = cerebro electrónico), el software (IDE para escribir y transferir el código) y la comunidad (ecosistema global que permite reutilizar librerías).

arduino · esqueleto básico (Clase 1 y 4)
// Estructura mínima obligatoria de todo sketch de Arduino
void setup () {
  // Codigo de configuracion inicial
  // Se ejecuta UNA sola vez al arrancar la placa
  pinMode (13 , OUTPUT ) ; // configura el pin 13 como salida
}

void loop () {
  // Codigo del bucle continuo
  // Se ejecuta de manera INFINITA mientras haya energia
  digitalWrite (13 , HIGH ) ; // inyecta 5V en el pin 13
}

2. Tinkercad y la Lógica del Circuito Físico

¿Por qué simulamos en Tinkercad Circuits?

  • Costo cero: permite experimentar con componentes caros sin comprarlos en fases tempranas.
  • Seguridad de activos: elimina el riesgo de destrucción física por errores de conexión (cortocircuitos).
  • Flexibilidad operativa: acceso desde cualquier dispositivo con navegador web.
⚠️ Simulación vs. realidad: en Tinkercad no hay falsos contactos ni caídas de tensión imprevistas; en el mundo real existen humedad, temperatura, desgaste y tolerancias. Regla de oro: la simulación valida la lógica del software, pero la implementación final requiere pruebas de campo en hardware físico.

El circuito eléctrico: camino cerrado

Es un camino cerrado y continuo por el cual se desplazan los electrones (corriente eléctrica). El flujo parte de un polo positivo (5V en Arduino) y debe retornar obligatoriamente a un polo negativo (GND o Tierra). Si el camino se interrumpe, el flujo se detiene por completo.

Las tres magnitudes fundamentales

MagnitudSímboloQué esUnidad
VoltajeVDiferencia de potencial o «presión» eléctrica (Arduino entrega típicamente 5V)Voltios (V)
CorrienteICaudal de electrones que circulan por segundoAmperios (A)
ResistenciaROposición física al paso de la corrienteOhmios (Ω)

La analogía hidráulica 🔧

  • Voltaje = presión del agua (determinada por la altura del tanque). A mayor altura, mayor fuerza potencial.
  • Corriente = caudal de agua (litros por segundo) que pasa por la tubería.
  • Resistencia = un estrechamiento intencional del caño (o una canilla entreabierta).
💡 Por qué es crítica la resistencia: un LED conectado directo entre 5V y GND se quema instantáneamente por exceso de corriente. Al colocar una resistencia (habitualmente 220 Ω) limitamos el flujo de electrones a un nivel seguro.

El proyecto Blink: ruta de la energía

Pin Digital de Arduino → Resistencia → LED → Pin GND

Componentes: 1) Placa Arduino Uno (cerebro lógico), 2) Diodo LED (salida visual), 3) Resistencia de 220 Ω (escudo protector). Cuando el programa ordena 5V al pin, el circuito se activa; cuando ordena 0V, el flujo se detiene.

3. Ley de Ohm, Serie/Paralelo y Protoboard

La Ley de Ohm

V = I × R
  • Con voltaje fijo (5V), si aumenta la resistencia → la corriente disminuye.
  • Si la resistencia cae cerca de cero → la corriente se dispara al infinito → cortocircuito.

Cálculo práctico: ¿por qué 220 Ω para un LED?

  • Datos del LED estándar: tolera 2V y requiere 0,02 A (20 mA) para brillar seguro.
  • Voltaje de Arduino: 5V → el voltaje a absorber por la resistencia es 5V − 2V = 3V.
R = V / I = 3V / 0,02A = 150 Ω (mínimo seguro)

*Se usa 220 Ω comercial porque ofrece un margen extra de seguridad para proteger el microcontrolador.

Conexión en Serie vs. Paralelo

SerieParalelo
Corriente (I)La misma en todo el caminoSe divide por cada rama autónoma
ResistenciasSe suman: RTotal = R1 + R2Cada rama es independiente
VoltajeSe divide entre los componentesTodos reciben el mismo 5V
Si falla uno…Se abre el circuito y TODOS se apagan (luces navideñas viejas)Los demás siguen funcionando
💡 Aplicación en gestión: toda la instalación eléctrica de una oficina se conecta en paralelo, justamente por la independencia operativa.

La Protoboard (placa de pruebas)

  • Canales de alimentación (bordes): líneas rojas (+) y azules (−), conectadas en horizontal. Distribuyen 5V y GND.
  • Pistas de trabajo (centro): filas numeradas por letras, conectadas en vertical. Aquí se pinchan sensores y actuadores.

Gestión de riesgos: el cortocircuito ⚡

Ocurre cuando 5V toca GND directamente sin pasar por ningún componente: R = 0 Ω → corriente al infinito. En Tinkercad aparece una advertencia; en hardware real la placa se sobrecalienta, el chip se destruye o se quema el puerto USB.

4. Anatomía del Código: setup() y loop()

El flujo de lectura lineal y cíclico

Un programa de Arduino (llamado sketch) se lee de arriba hacia abajo, línea por línea, de manera rígida. A diferencia de una aplicación web (que permanece inactiva esperando un clic), el firmware embebido no descansa: ejecuta sus instrucciones de forma automatizada y vuelve a empezar de inmediato, de manera perpetua.

El esqueleto obligatorio

  • setup(): bloque de preparación e infraestructura inicial. Se ejecuta una única vez al recibir energía o al presionar Reset. Aquí se configuran pines (entradas/salidas) y se abren canales de comunicación.
  • loop(): bloque operativo central. Se ejecuta de manera infinita y cíclica: al llegar a la última línea regresa a la primera. Aquí va el monitoreo constante de activos (alarmas, sensores de stock).
arduino · los dos bloques nativos (Clase 4)
void setup () {
  // Inicializacion del sistema
  // Configuracion de periferiales
  pinMode (13 , OUTPUT ) ; // el pin 13 sera salida
}

void loop () {
  // Reglas de negocio repetitivas
  digitalWrite (13 , HIGH ) ; // enciende
  delay (1000) ;              // espera 1 segundo (1000 ms)
  digitalWrite (13 , LOW ) ;  // apaga
  delay (1000) ;              // espera otro segundo
} // al cerrar la llave, el loop vuelve a empezar: parpadeo infinito

Sintaxis crítica de C++ ⚠️

ReglaQué haceError típico
Punto y coma (;)Cierra cada instrucción, como el punto final de una oraciónOlvidarlo paraliza la compilación
Llaves { }Delimitan la «zona de influencia» de cada función o bloqueDejar una sin cerrar
Case sensitivityEl lenguaje distingue mayúsculas/minúsculasEscribir digitalwrite en vez de digitalWrite
Comentarios //El compilador los ignora; sirven para que otros programadores entiendan la lógica (auditoría)—

5. Salidas Digitales e Interacción Binaria

¿Qué significa «digital»?

El sistema se reduce estrictamente a dos estados lógicos excluyentes: no existen matices ni valores intermedios.

EstadoVoltajeLógicaBinario
HIGH (nivel alto)5V (presencia de tensión)Encendido / Verdadero1
LOW (nivel bajo)0V o masa (ausencia)Apagado / Falso0

Comandos de configuración y escritura

  • pinMode(numeroPin, OUTPUT) — se declara en setup(). Los pines 0 a 13 son de propósito general; OUTPUT le indica al chip que ese pin actuará como proveedor de energía hacia el exterior.
  • digitalWrite(numeroPin, ESTADO) — se usa en loop(). Con HIGH el pin se conecta internamente a la línea de 5V; con LOW, a tierra (GND, 0V).

La gestión del tiempo: delay()

El chip procesa millones de operaciones por segundo: si encendemos y apagamos sin pausa, el ojo humano no nota el cambio. delay() pausa el flujo en milisegundos (1 segundo = 1000 ms).

⚠️ Efecto secundario clave: durante el delay el chip queda completamente «congelado». No lee sensores ni procesa otras órdenes.
arduino · control de baliza intermitente (Clase 6)
void setup () {
  pinMode (13 , OUTPUT ) ; // configura el pin 13 como salida
}

void loop () {
  digitalWrite (13 , HIGH ) ; // inyecta 5V (enciende baliza)
  delay (1000) ;              // espera 1 segundo
  digitalWrite (13 , LOW ) ;  // corta la tension a 0V (apaga)
  delay (1000) ;              // espera 1 segundo
}

💡 Ejemplo del foro: para una sirena intermitente rápida (½ segundo ON, ½ OFF) el parámetro de delay() debería ser 500.

6. Entradas Digitales y Captura del Entorno

La placa como «oyente»

Una entrada digital es el camino inverso a la salida: la placa actúa como un voltímetro digital que mide constantemente un pin para saber qué ocurre en el exterior. Si un sensor inyecta 5V, el chip interpreta HIGH (1); si el paso de energía se corta a 0V, interpreta LOW (0).

Comandos de lectura

  • pinMode(numeroPin, INPUT) — en setup(). INPUT configura el pin en alta impedancia, transformándolo en un sensor interno capaz de detectar voltajes sin alterar el circuito.
  • digitalRead(numeroPin) — en loop(). Devuelve un entero: 1 si detectó 5V, 0 si detectó 0V. Buena práctica: guardar el resultado de inmediato en una variable int.

Acoplamiento directo entrada→salida

La forma más elemental de automatización: transferir el estado de una entrada directamente a una salida, como puente de software. Caso práctico de la cátedra: un pulsador de pánico en la entrada de la oficina que, al presionarlo (5V), enciende al instante un reflector de contingencia exterior.

arduino · transferencia de estados (Clase 7)
int estadoBoton = 0; // variable global para guardar el dato leido

void setup () {
  pinMode (13 , OUTPUT ) ; // pin 13 actuara como salida (LED)
  pinMode (2 , INPUT ) ;   // pin 2 actuara como entrada (Boton)
}

void loop () {
  estadoBoton = digitalRead (2) ;    // lee la entrada y guarda el dato (1 o 0)
  digitalWrite (13 , estadoBoton ) ; // escribe en la salida el dato guardado
} // el LED replica en vivo lo que hace el boton

7. Toma de Decisiones: if/else e Interrupciones

La estructura condicional if

El sistema adquiere «inteligencia» cuando altera su comportamiento según los datos que recolecta. La estructura if evalúa una condición: si es verdadera, ejecuta el bloque entre llaves; si es falsa, ignora esas líneas y continúa hacia abajo.

La cláusula else («de lo contrario») ejecuta la acción alternativa. Nunca lleva condición propia y funciona de forma binaria y excluyente: se ejecuta el if O el else, jamás ambos en el mismo ciclo.

Operadores relacionales ⚠️

OperadorSignificadoEjemplo
==Estricta igualdad (comparación)if (estado == HIGH)
!=Distinto deif (sensor != 0)
> / <Mayor / menor que (umbrales numéricos)if (lectura > 700)
⚠️ Peligro en gestión: usar un solo signo = es una asignación, no una comparación. Provoca que la condición sea siempre verdadera y rompe el software. Ejemplo de error del foro: if (sensor = LOW) en vez de ==.
arduino · automatización de luces por presencia (Clase 8)
int sensor = 0; // variable global para la lectura del sensor

void setup () {
  pinMode (4 , INPUT ) ;  // pin 4: sensor de presencia (entrada)
  pinMode (12 , OUTPUT ) ; // pin 12: luz del pasillo (salida)
}

void loop () {
  sensor = digitalRead (4) ; // lee el sensor cada ciclo
  if ( sensor == HIGH ) {          // regla: si hay operarios...
    digitalWrite (12 , HIGH ) ;    // ...enciende la luz
  } else {                         // de lo contrario...
    digitalWrite (12 , LOW ) ;     // ...apagala (ahorro energetico)
  }
}

El problema del Polling

Hasta ahora el Arduino lee sensores por polling (encuesta constante dentro del loop). Si la línea 4 tiene un delay(5000), el sistema queda «ciego» 5 segundos: si un operario presiona el botón de parada de emergencia en el segundo 2 del delay, el sistema no se entera y ocurre un accidente.

Interrupción por Hardware (Interrupt)

Mecanismo físico que detiene inmediatamente la ejecución del código ante un evento externo urgente, sin importar que el chip esté en un delay. Analogía de la cátedra: estás leyendo un informe línea por línea (loop); suena la alarma de incendios (evento externo); congelás tu actividad, evacuás (atención de emergencia) y volvés a la misma palabra donde habías quedado.

  • Pines habilitados en Arduino Uno: solo el pin 2 (Interrupción 0) y el pin 3 (Interrupción 1).
  • Modos de disparo: RISING (activa cuando el pin pasa de 0V a 5V, flanco de subida) y FALLING (pasa de 5V a 0V, flanco de bajada).
arduino · registro de la interrupción (Clase 8)
attachInterrupt ( digitalPinToInterrupt (2) , emergencia , RISING ) ;
// Parametro 1: pin fisico a escuchar (pin 2)
// Parametro 2: nombre de la funcion de emergencia a ejecutar
// Parametro 3: modo de disparo electrico (RISING = flanco de subida)

La ISR (Interrupt Service Routine)

Reglas estrictas de la función que se ejecuta al saltar la alarma:

  • Debe ser lo más corta y rápida posible.
  • No recibe parámetros ni devuelve valores (void).
  • ⚠️ Dentro de una ISR la función delay() no funciona: el contador de tiempo interno del chip también se congela.
arduino · sistema con parada de emergencia (Clase 8)
void setup () {
  pinMode (13 , OUTPUT ) ; // LED de proceso normal
  pinMode (8 , OUTPUT ) ;  // salida de la alarma de emergencia
  pinMode (2 , INPUT ) ;   // boton de parada de emergencia

  attachInterrupt ( digitalPinToInterrupt (2) , emergencia , RISING ) ;
  // registra la interrupcion: al subir el pin 2 de 0V a 5V se ejecuta emergencia()
}

void loop () {
  digitalWrite (13 , HIGH ) ;
  delay (3000) ; // bucle lento... pero la interrupcion responde al instante
  digitalWrite (13 , LOW ) ;
  delay (3000) ;
}

Nota: la función emergencia() (la ISR) aparece como llamada en el PDF; su cuerpo completo está cortado en la diapositiva. En tu práctica, definila como void emergencia() { digitalWrite(8, HIGH); } o similar.

8. Entradas Analógicas y el ADC

Señales continuas vs. discretas

Hasta ahora trabajamos con lógica binaria (HIGH/LOW), pero las variables críticas de los procesos logísticos y térmicos no son un 0 o un 1: la temperatura de una oficina, la presión de una caldera, el nivel de un tanque o la luz exterior cambian suavemente, pasando por un número infinito de valores intermedios.

Para procesar ese mundo continuo se necesitan dos pasos: 1) el transductor (sensor) convierte la variable física (calor) en una variable eléctrica proporcional (un voltaje entre 0V y 5V); 2) la cuantificación: el chip convierte ese voltaje analógico en un código numérico binario.

El convertidor ADC de 10 bits

El Arduino Uno tiene un ADC (Analog-to-Digital Converter) interno que divide la tensión de entrada (0–5V) en «escalones» discretos. Con una resolución de 10 bits genera 2¹⁰ = 1024 combinaciones: el voltaje se mapea linealmente a un entero entre 0 y 1023.

Voltaje real en el pinLectura digital (RAM)
0,00 V0
1,25 V255
2,50 V511
3,75 V767
5,00 V1023

Los valores intermedios se redondean al escalón más cercano. Precisión por paso: ≈ 4,88 mV.

Los pines analógicos A0–A5

  • Las señales analógicas no se conectan en los pines 0-13: existe un bloque exclusivo etiquetado ANALOG IN, con 6 pines (A0 a A5).
  • Ventaja sintáctica: ya vienen configurados como entradas por hardware → no es obligatorio declararlos con pinMode().
  • analogRead(A0) devuelve un int entre 0 y 1023. Es más lento que digitalRead(): requiere ~100 microsegundos para estabilizar y muestrear.

El potenciómetro como simulador

Resistencia de tres terminales con perilla giratoria: extremo 1 a 5V, extremo 2 a GND, y la terminal central (señal) al pin analógico. Al girar la perilla entrega un voltaje limpio y variable entre 0V y 5V — perfecto para practicar antes de cablear sensores industriales.

arduino · lectura y umbral de alarma (Clase 9)
int lecturaCruda = 0;

void setup () {
  pinMode (13 , OUTPUT ) ; // alerta visual
}

void loop () {
  lecturaCruda = analogRead ( A0 ) ; // lee el voltaje actual (0 a 1023)

  if ( lecturaCruda > 700) {       // umbral critico 700 (aprox 3,4V)
    digitalWrite (13 , HIGH ) ;    // dispara contingencia
  } else {
    digitalWrite (13 , LOW ) ;     // operacion normal
  }
}

9. Salidas Analógicas Simuladas (PWM)

La limitación física de las salidas

Los pines de salida son estrictamente binarios: solo entregan de forma real 0V (LOW) o 5V (HIGH). El hardware no puede generar tensiones intermedias. Pero en gestión necesitamos graduar: el extractor de HVAC a velocidad proporcional a la temperatura, o las luces de oficina atenuadas según la luz solar.

El principio PWM (Pulse Width Modulation)

La solución sin hardware caro: encender y apagar el pin a alta velocidad (~500 veces por segundo). El actuador (motor, LED) no llega a apagarse por su propia inercia y experimenta un voltaje promedio ponderado, simulando una señal analógica real.

El Ciclo de Trabajo (Duty Cycle)

Proporción de tiempo que el pulso permanece encendido frente al ciclo total:

Ciclo de trabajoComportamientoVoltaje equivalente
0 %El pin está todo el tiempo en 0V0 V
50 %La mitad del tiempo en 5V, la otra mitad en 0V2,5 V
100 %El pin está todo el tiempo en 5V5 V

Pines habilitados y resolución de 8 bits

  • Solo los pines marcados con el símbolo ∼ soportan PWM en el Uno: 3, 5, 6, 9, 10 y 11. Si lo aplicamos en un pin sin ∼ (ej: pin 7), se comporta como salida digital común.
  • Resolución de 8 bits → 2⁸ = 256 valores: el rango va de 0 (0 %, apagado) a 255 (100 %, potencia máxima). Comparado con el ADC de entrada (10 bits, 0-1023).
  • analogWrite(numeroPin, valorPotencia): los pines PWM tampoco requieren pinMode() obligatoria.

  // Los pines PWM no requieren configuracion mandatoria
}

  brillo = brillo + 5;        // incrementa la intensidad gradualmente

10. Comunicación Serie y Depuración

La necesidad de visibilidad

Nuestros circuitos eran «mudos»: solo sabíamos si el software funcionaba por el encendido de un LED. El administrador de TI no puede adivinar qué valor exacto procesa la RAM: hay que extraer la información interna del chip hacia un panel legible para humanos.

El protocolo UART

Arduino usa UART (Universal Asynchronous Receiver-Transmitter) o puerto serie: los bits viajan en fila, uno detrás del otro, por un único hilo. En hardware real se usan los cables TX (transmisión) y RX (recepción); en Tinkercad y laboratorio todo viaja por el mismo cable USB que alimenta la placa.

Comandos clave

ComandoFunción

Serial.print(x)Envía el dato de forma continua: lo próximo sale al lado, en la misma línea.
Serial.println(x)Envía el dato + un salto de línea («Enter» invisible): lo próximo sale abajo.

El Monitor Serie

Ventana de consola integrada en el IDE y en la esquina inferior del panel de código de Tinkercad. Muestra cronológicamente los strings y números que la placa transmite en tiempo real. Es la herramienta por excelencia del Debugging (detección de fallas lógicas).

⚠️ Buena práctica de telemetría: no imprimas dentro del loop sin freno de tiempo — el chip enviaría datos miles de veces por segundo, saturaría el monitor y volvería ilegible la lectura. Toda impresión de diagnóstico debe acompañarse de un delay() prudencial.

11. Sensor de Ultrasonido HC-SR04

El principio del eco

Para medir distancias en logística (nivel de un silo de granos, stock de estanterías) se usa el HC-SR04. Imita la ecolocalización de los murciélagos: emite una ráfaga de ondas sonoras de alta frecuencia (inaudibles) y mide cuánto tiempo tarda la onda en chocar contra un objeto y regresar.

Pines del componente

PinRol
VCCAlimentación de energía (5V)
GNDTierra común (0V)
Trigger (Disparador)Entrada digital: recibe del Arduino la orden de lanzar la ráfaga de ultrasonido
Echo (Receptor)Salida digital: avisa al Arduino el tiempo que duró el viaje de la onda

Protocolo de activación del Trigger

  1. Asegurar que el pin esté apagado (LOW).
  2. Inyectar tensión (HIGH) durante exactamente 10 microsegundos.
  3. Volver a apagar el pin (LOW).

Ese pulso le indica al sensor que despache 8 pulsos de ultrasonido a 40 kHz. Luego el pin Echo pasa a HIGH y permanece encendido hasta recibir el eco: medimos esa duración con la función nativa pulseIn(pinEcho, HIGH), que guarda el tiempo en microsegundos en una variable long.

De microsegundos a centímetros

El sonido viaja a ≈ 343 m/s = 0,0343 cm/microsegundo. Como Distancia = Velocidad × Tiempo, y la onda hace el viaje de ida Y vuelta, hay que dividir por 2:

Distancia = (Tiempo × 0,0343) / 2 ≈ Tiempo / 58,3
arduino · medidor de distancia (Clase 12)
int pinTrigger = 9;
int pinEcho = 10;
long duracion = 0;   // pulseIn devuelve microsegundos: hace falta tipo long
int distancia = 0;

void setup () {
  Serial . begin (9600) ;
  pinMode ( pinTrigger , OUTPUT ) ; // Trigger: pin de salida (ordena el disparo)
  pinMode ( pinEcho , INPUT ) ;     // Echo: pin de entrada (mide el retorno)
}

void loop () {
  digitalWrite ( pinTrigger , LOW ) ;
  delayMicroseconds (2) ;           // garantiza el pin apagado antes del pulso
  digitalWrite ( pinTrigger , HIGH ) ;
  // (en la practica: mantener HIGH 10 microsegundos con delayMicroseconds(10)
  //  y luego volver a LOW — la diapositiva del PDF se corta aqui)
}

⚠️ La diapositiva 9-10 del PDF está cortada: termina en digitalWrite(pinTrigger, HIGH);. El patrón completo del protocolo visto en la teoría es: HIGH 10 µs → LOW → duracion = pulseIn(pinEcho, HIGH); → distancia = duracion / 58,3; → imprimir por Serial. El bloque de cierre (Evaluación y Cierre) no aporta más líneas de código.

Servomotor: posicionamiento angular de precisión

A diferencia de un motor DC común (que gira sin parar al recibir energía), un servomotor se mueve hacia un ángulo exacto y se sostiene firme en esa posición. Aplicación empresarial: barreras de parking automáticas, cerraduras digitales, direccionamiento de cintas transportadoras.

El Relé: el puente hacia la alta tensión ⚡

⚠️ Restricción crítica: un pin de Arduino solo tolera 20-40 miliamperios a 5V. Conectar directo un motor industrial, una luminaria de 220V o una bomba de agua quema el chip instantáneamente y puede provocar un cortocircuito severo.

Un Relé es un interruptor operado magnéticamente que separa físicamente el circuito de control (baja potencia) del circuito de potencia (alta tensión): el aislamiento galvánico. Del lado Arduino, al recibir un HIGH (5V) una bobina (electroimán) se magnetiza y atrae un contacto metálico; del lado maquinaria, los contactos actúan como una llave de luz común que abre o cierra los 220V externos, totalmente aislados.

Bornes de salida del relé

BorneComportamientoIdeal para
COM (Común)Ingresa la fase eléctrica externa (220V)—
NO / NA (Normalmente Abierto)Circuito cortado por defecto; al activar el pin, el relé CIERRA y la máquina recibe energíaAlarmas, luces
NC (Normalmente Cerrado)Conectado por defecto; al activar el pin, el relé ABRE y corta la energíaSistemas de refrigeración

Como el relé se activa mediante un optoacoplador digital común, se programa con el estándar digitalWrite():

arduino · control de relé por software (Clase 14)
int pinRele = 7;

void setup () {
  pinMode ( pinRele , OUTPUT ) ; // el pin 7 comandara la bobina del rele
}

void loop () {
  digitalWrite ( pinRele , HIGH ) ; // activa el electroiman: cierra el contacto
  delay (5000) ;                    // la carga externa queda energizada 5 s

  digitalWrite ( pinRele , LOW ) ;  // libera la bobina: abre el contacto
  delay (5000) ;                    // la carga externa queda apagada 5 s
}

14. Internet de las Cosas (IoT)

El paradigma IoT

Hasta ahora los sistemas embebidos operaban aislados (Edge). El IoT consiste en dotar a los objetos cotidianos e industriales de conectividad de red. El valor para la gestión no es el hardware en sí, sino recopilar telemetría masiva en tiempo real, centralizarla en servidores remotos y optimizar costos operativos y logísticos.

Las tres capas de un sistema IoT

  1. Capa de Percepción (Hardware): sensores y microcontrolador (Arduino) que capturan la realidad física.
  2. Capa de Red (Conectividad): routers, antenas WiFi o módems celulares que transportan los bits.
  3. Capa de Aplicación (Nube): servidores y bases de datos que procesan la información y la muestran en Dashboards.

Protocolos ligeros: MQTT

Una PC usa protocolos pesados (HTTP) para cargar páginas web, pero un microcontrolador tiene RAM muy limitada y no puede procesar HTML masivo. Necesita protocolos de bajo consumo: el estándar IoT por excelencia es MQTT (Message Queuing Telemetry Transport), basado en el modelo de Publicación y Suscripción mediante un servidor central (Broker).

Hardware de conectividad: Shield Ethernet W5100 (puerto de red RJ45) o los módulos ESP8266 / ESP32 — el estándar actual: chips económicos con WiFi nativo y pila TCP/IP.

El formato JSON y las plataformas

Para enviar datos a la nube de forma ordenada se usa JSON (JavaScript Object Notation), texto plano muy ligero:

{ "sensor_id": "Silo_A", "nivel": 78 }

Plataformas de visualización: ThingSpeak (analítica de sensores abierta), Blynk / Adafruit IO (apps móviles con botones y gráficos arrastrando componentes).

15. Infraestructura Web y HTML

Cómo funciona la Web: los 5 pasos

La visualización de una página comienza al teclear la URL o seguir un hipervínculo; el navegador inicia una serie de comunicaciones transparentes para el usuario:

  1. DNS: se traduce el nombre del servidor de la URL en una dirección IP usando la base de datos distribuida de Internet. Sin la IP no se puede contactar al servidor ni enviarle paquetes.
  2. Petición HTTP: el navegador solicita el recurso. Primero pide el texto HTML y, al analizarlo, hace peticiones adicionales por los gráficos y otros ficheros de la página. Las estadísticas de un sitio se basan en «páginas vistas» o «peticiones de servidor».
  3. Renderizado: al recibir los ficheros, el navegador renderiza la página según el HTML, el CSS y otros lenguajes; al final incorpora imágenes y recursos para producir la pantalla final.
  4. Hiperenlaces: la mayoría de las páginas contienen enlaces a otras páginas, descargas, documentos fuente y otros recursos.
  5. La Web: esta colección de recursos interconectados por hipertexto es la «red de información» que Tim Berners-Lee llamó WorldWideWeb en 1990.

HTML: definición

HTML (HyperText Markup Language) es un lenguaje de etiquetado que permite escribir páginas Web. Es muy sencillo de usar; permite describir hipertexto (texto presentado como enlaces a otros documentos) y referenciar objetos multimedia. La descripción especifica la estructura lógica del contenido (títulos, párrafos, enumeraciones, citas) y los efectos deseados, dejando la presentación final al navegador. Todo se maneja mediante etiquetas o tags: palabras reservadas encerradas entre ángulos <etiqueta>.

17. ¿Qué es PHP?

Definición

PHP (acrónimo de «PHP: Hypertext Preprocessor») es un lenguaje de código abierto, interpretado, de alto nivel, embebido en páginas HTML y ejecutado en el servidor.

A diferencia de Java o JavaScript (que se ejecutan en el navegador), PHP corre en el servidor: eso permite acceder a los recursos del servidor, como una base de datos. El programa PHP se ejecuta en el servidor y el resultado se envía al navegador — normalmente una página HTML (o WML).

¿Qué se puede hacer con PHP?

  • Construir páginas dinámicas en un entorno Web.
  • A nivel sistemas, desarrollar cualquier sistema (aún los más complejos) sin problemas.
  • Acceder a librerías externas y bases de datos.

Ventajas de PHP

VentajaDetalle
RápidoEl tiempo de pre-procesado es rápido
GratuitoNo se paga para su utilización
Fácil de usarSintaxis simple
VersátilSe ejecuta en una variedad de sistemas operativos
SeguroEl código PHP queda oculto en el servidor
AdaptableAl ser código abierto puede ser modificado
Amplio soporteComunidad enorme de programadores

Ejemplos de sitios con PHP: Drupal, Joomla, Moodle.

Características principales

  • Interactúa con Forms: procesa la información que el usuario carga.
  • Comunicación con bases de datos.
  • Genera páginas Web seguras.
  • Se combina con JavaScript.

Versiones según la clase: 5.x (fundamental: POO), 4.x (mejoras de velocidad/seguridad), 3.x (discontinuada).

¿Qué se necesita para correr PHP?

  • Sistema operativo (Windows, Linux, MacOS, Unix…).
  • Servidor Web (preferentemente APACHE).
  • PHP instalado — en la práctica: el paquete Wamp (con su configuración de Apache, de PHP y de Wamp).

La sentencia switch

Es similar a una serie de IF sobre la misma expresión. Importante entender su ejecución para evitar errores: switch ejecuta línea por línea; al comienzo no se ejecuta código. Solo cuando encuentra un case cuyo valor coincide con la expresión comienza a ejecutar, y continúa hasta el final del bloque o hasta el primer break. Si no se escribe break, PHP seguirá ejecutando las sentencias del siguiente case (efecto cascada). El default coincide con todo lo que no coincidió en los otros case.

php · switch con default (Clase 1 PHP)
<?php
   switch ($i) {
      case 0:
         print "i es igual a 0";
         break;            // sin el break seguiria ejecutando el case 1, 2 y default
      case 1:
         print "i es igual a 1";
         break;
      case 2:
         print "i es igual a 2";
         break;
      default:
         print "i no es igual a 0, 1 o 2";
   }
?>

20. Funciones

Definición

Son un conjunto de instrucciones o sentencias que realizan una tarea específica y como resultado puede devolver o no un valor. Se dividen en: definidas por el usuario y predefinidas por PHP.

Reglas de las funciones de usuario

  • No es necesario definirlas antes de ser llamadas.
  • Los nombres son sensibles a mayúsculas y minúsculas.
  • Se pueden definir funciones dentro de funciones.
  • Cualquier instrucción o sentencia válida en PHP puede incorporarse en una función.

Parámetros

La información se suministra a través de los parámetros: una lista de variables y/o constantes separadas por coma. PHP soporta tres modos:

21. Matrices (Arrays)

Definición

Una matriz en PHP es un tipo de datos que asocia valores con claves. Puede usarse como matriz real, lista o vector, tabla asociativa, diccionario, colección, pila, cola e incluso árbol.

  • Una clave puede ser de tipo entera o string; los valores decimales serán truncados.
  • Si no se especifica clave, se usa el máximo de los índices enteros + 1. Si se especifica una clave ya asignada, el valor se reemplaza.
  • Se crea con la construcción del lenguaje array(), que toma parejas clave => valor.
  • Modificar: $matriz[clave] = valor; (si no existe la variable, se crea). Remover una pareja clave/valor: unset().

22. Bases de Datos y MySQL desde PHP

¿Qué es una base de datos?

Es una aplicación que almacena una colección de datos, con su propio conjunto de programas para manipularla (crearla, insertar datos, eliminarlos, reordenarla…). Motores de base de datos: MySQL, Oracle, Sybase, PostgreSQL, SQLServer, etc.

¿Por qué una BD? Sin BD, las páginas generadas con PHP serían estáticas (sin actualización de información). Siempre es necesario almacenar datos para luego consultarlos — ej: un foro almacena todos los envíos sobre un tema para luego mostrarlos, buscarlos, etc.

Ventajas: mantenimiento y escalabilidad, portabilidad, búsqueda, seguridad, performance.
Características: lenguaje de consulta (SQL – Structured Query Language), integridad referencial (PKs, FKs), índices, manejo de transacciones, procedimientos y triggers.

WHERE condicion;
